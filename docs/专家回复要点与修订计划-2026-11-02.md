## 一、四个问题的结论

### Q1　弱纹理还值得在"重建后端"上投入吗？
**不值得。** 白瓷砖的"白雾"是**光度信息缺失的物理极限**，不是算法没调好：
- 3DGS 拟合的是多视图光度一致性，缺高频纹理 → 梯度极小 → 高斯在深度方向被无限拉长（就是雾）
- VGGT 的学习先验也补不出物理几何（我们实测 VGGT+3DGS 只有 14.43 dB）
- 业界共识：弱纹理要引入**外部约束**（深度传感器/LiDAR/IMU/CAD 先验），而不是改优化器

**改成三件事**：
1. **前端采集引导**：实时算特征点密度/光流，纹理不足或运动模糊时 AR 提示"靠近拍/横向平移/贴参照物（A4 纸、硬币）"
2. **尺度锚点**：让用户框选一个已知尺寸（门框 2.1 m、地砖 600×600 mm）作为全局 scale anchor
3. **降级重建策略**：判定为弱纹理的素材，放弃高精度 3DGS，改用**强正则化的传统 MVS（ACMMP/PatchMatch）+ 曼哈顿世界假设**，强制拉平墙面 —— 换"结构可用"，不要"视觉逼真"

### Q2　只有一面可信竖墙时，房间盒怎么做？
**选方案 a（弱假设），不要稠密点半空间求交。** 后者在雾上极易拟合歪，反而污染唯一正确的墙面。

具体算法（可直接实现）：
1. 取可信竖墙法向 `n1` 与重力 `g`
2. 构造正交基：`n2 = normalize(g × n1)`，`n3 = g`
3. 地面点投影到 `n2` 轴，取 **5%~95% 分位数**作该方向宽度（比极值抗噪）
4. 高度直接取**相机高度分布的众数/均值**（假设持握高度恒定）
5. **置信度分级**：≥2 面墙 → 全几何（sane）；**1 面墙 → 曼哈顿补全（sane，但标记"推测"）**；0 面墙 → 只输出轨迹凸包，不生成盒（sane=false）
6. 可选语义辅助：检测到门/窗就把其所在平面当墙约束

### Q3　家具盒：几何分割 vs 学习式检测？
**1~2 人周内选"学习式检测 + 深度反投影"**，纯几何是地狱难度（雾里点云断裂/粘连，启发式规则工程量远超 2 周）。

管线：关键帧跑 **Grounding DINO** → 2D 框 + 类别 → 框内像素取**深度中位数** → 用内参反投影成 3D AABB → **贴地吸附**（用房间盒地面）+ **按类别的尺寸先验**过滤异常 → 几何 OBB 只在纹理丰富处做微调（锦上添花）。

> 一句话：**语义正确的大致盒子 > 尺寸精确但语义错误的几何体**。

### Q4　精度怎么报？
**别只报"中心误差"，用三级指标**：
- **L1 相对精度**（合成，基础线）：AABB 中心误差 <4 cm，尺寸 IoU >0.8
- **L2 绝对精度**（真实场景，验收线）：10+ 个真实场景用**激光测距仪**打点，报 **90% 分位数**误差（<3 cm），不报平均值
- **L3 语义/结构**：房间盒生成成功率、家具盒语义准确率（Precision/Recall）
- 必须写明前置条件（特征点密度、重叠率、已校正尺度）；给**误差热力图**不要只给数字
- **纯合成数据不能作为精度声明**（评审不认）；弱纹理/未校正尺度下**绝不承诺绝对精度**

# 单墙房间盒补全（P0-1，2026-11-02）

> 依据：专家的 Q2 结论 —— 只有 1 面可信竖墙时，选"地面平面 + 相机高度 + 曼哈顿正交先验"
> 的**弱假设方案**，不要"稠密点半空间求交"（雾上会拟合歪，反而污染唯一正确的墙）。

## 一、做了什么

`tools/structure_room.py` 新增 `complete_room_from_single_wall()`：
1. 可信墙法向 `n1`（投影掉竖直分量）→ 由重力 `up` 得第三轴 `n2 = up × n1`
2. 地面点投影到 `n1/n2`，取 **5%~95% 分位**作为长宽（分位数抗噪）
3. 层高取**地面上方最靠上的强平面峰**（天花），而不是 P98 分位
4. 地面**尺度无关**估计：取点云 up 轴最低 2% 分位；相机高度只作校验

`tools/scene_structure.py` 接入：`sane=false 且 len(real_walls)==1` → 走补全 →
`sane=true` + **`estimated=true`** + `estimation` 证据；场景模式改为 `room`。

## 二、实测精度（唯一能"量出来"的地方）

拿 **room-real**（人工核对过 17.14×9.19×2.88 m）的**一面墙**做补全：

| 项 | 真值 | 补全 | 相对误差 |
| --- | --- | --- | --- |
| 长 | 17.14 | 13.88 | **10.3%** |
| 宽 | 9.19 | 10.34 | **12.5%** |
| 高 | 2.88 | 3.18 | **19.0%** |

对照：**5 面墙全几何拟合误差 0/0.9/0.1%**。所以补全的价值是"从 0 到可用"，
不是"精确"—— 界面必须标"推测"。

白瓷砖卫生间（原本 0 盒）：补出 15.47×12.75×24.91 单位（按 0.09 m/单位 ≈ 1.4×1.15×2.24 m），
方向正确、尺寸保守。

## 三、这轮抓到的三个真 bug

### 1. 「眼高 1.5」是按米写死的，在非米制重建上把地面算错
白瓷砖那份 1 单位 ≈ 0.09 m，`floor = 相机高度 − 1.5 单位` 只降了 0.13 m →
地面落进点云中间（up 坐标 P1 到 −15.4），下游全错。
→ 改成**尺度无关**：地面取点云 up 轴最低 2% 分位；用"整体缩放 3 倍、盒子也 ≈3 倍"做回归测试。

### 2. 层高用 P98 分位 → 被雾/野点撑成"竖塔"
云在 up 方向 P99 到 11.1（相对地面 26.6 单位）→ 房间盒 15.5×12.8×26.4（高 > 长宽）。
→ 改成取"地面上方最靠上的**强平面峰**"（天花）。仍受雾影响，需素材质量配合。

### 3. 重力投票：**收益未证实、风险已证实**
试过"点云平面投票"定重力（专家的建议方向之一）：

| 方案 | up | 墙数 | 房间盒 | 误差 |
| --- | --- | --- | --- | --- |
| 投票关闭 | [0.059,-0.998,-0.01] | 5 | 17.15×9.28×2.88 | 0/0.9/0.1% |
| 投票开启 | [0.295,-0.08,0.952] | **0** | 10.94×3.45×2.6 | 9.8/**62.5**/36.2% |

而它本来要救的白瓷砖素材，投票也判定"相机方向更好"（没救到）。
→ **默认关闭**，留 `DSH_GRAVITY_VOTE=1` 做对照。教训：先量再改。
