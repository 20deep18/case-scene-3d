# 开源插件与依赖清单

本系统坚持「**零 npm 依赖 + 最小 Python 依赖**」的原则：后端只用 Node 内置模块，
前端只用本地化的 Three.js，避免供应链与离线部署问题。下面列出全部实际使用到的开源组件、
用途、许可证，以及被评估但未采用（或暂时被本机环境阻塞）的方案。

---

## 一、实际使用的组件

### 前端

| 组件 | 版本 | 用途 | 许可证 | 引入方式 |
| --- | --- | --- | --- | --- |
| [Three.js](https://github.com/mrdoob/three.js) | 0.180.0 | 场景图、相机、矩阵/四元数数学、OrbitControls | MIT | 已本地化到 `vendor/three`，通过 `index.html` 的 importmap 引入，**不使用 CDN** |
| 自研 `splat-renderer.js` | — | WebGL2 3DGS 渲染（球谐、EWA、基数排序、预乘 alpha） | 本项目 | 不依赖第三方 splat 渲染库 |
| 自研 `pnp.js` | — | PnP 相机位姿解算（Jacobi 特征分解、3×3 SVD、DLT + Hartley 归一化、LM 精修） | 本项目 | 纯 JS，无第三方数学库 |

> 为什么自己写而不直接用现成的？我们评估过 antimatter15/splat、mkkellogg/GaussianSplats3D、
> @mkkellogg/gaussian-splats-3d、gsplat.js 等，结论见下节。

### 后端

| 组件 | 版本 | 用途 | 许可证 |
| --- | --- | --- | --- |
| Node.js 内置模块 | ≥ 18 | HTTP 服务、文件 I/O、WebSocket 帧解析（自实现 RFC6455）、crypto | MIT（Node.js 本体） |
| 自研 `ws.js` | — | WebSocket 服务端（握手、掩码、分片、ping/pong） | 本项目 |

**没有使用** `express`、`ws`、`socket.io`、`cors`、`multer`、`chokidar` 等常见 npm 包——
全部用内置能力替代，因此项目克隆下来**不需要 `npm install`** 即可运行。

### 被评估但未安装 / 未采用

| 组件 | 为什么评估 | 结论 |
| --- | --- | --- |
| [COLMAP](https://github.com/colmap/colmap) | 稀疏重建与相机位姿估计的标准工具 | **代码已支持**（`pipeline/colmap_recon.py` 同时支持 pycolmap 与 colmap 命令行），但本机没有 MSVC 无法编译，官方也没有匹配的预编译包，需要用户自行安装（见部署文档 §5） |
| [pycolmap](https://github.com/colmap/colmap) | COLMAP 的 Python 绑定，可免装命令行 | 官方 PyPI 只有 `cp310` 轮子（**非** abi3），在 Python 3.12 下 `import pycolmap` 会报 `Cannot import the C++ backend pycolmap._core`。若要使用，请配 Python 3.10 环境 |
| [gsplat](https://github.com/nerfstudio-project/gsplat) | NVIDIA 官方推荐的 3DGS CUDA 光栅化库，速度快 | 官方 release 里 **Windows 轮子最高只到 cu124**（`gsplat-1.5.3+pt24cu124-cp310-cp310-win_amd64.whl`）。本机 RTX 5060 是 **sm_120**，需要 cu128+，因此该轮子无法使用；源码编译又需要 MSVC。**这就是我们自研 `train_gpu.py` 的原因**（`pipeline/train_gsplat.py` 仍保留，环境具备时会自动启用） |
| [graphdeco-inria/gaussian-splatting](https://github.com/graphdeco-inria/gaussian-splatting) | 3DGS 原版官方实现 | 需要编译 `diff-gaussian-rasterization` + `simple-knn` CUDA 扩展，同样需要 MSVC。我们的训练器**遵循其参数化、损失与致密化策略**，导出的 PLY 与其完全兼容 |
| [antimatter15/splat](https://github.com/antimatter15/splat) | 最经典的 Web splat 查看器，定义了 `.splat` 32 字节格式 | 作为 **.splat 格式规范**采用（我们的 `to_splat.py` 与 `splat-loader.js` 按该格式实现），但渲染器自己写（需要与标注、相机、协同系统深度集成） |
| [mkkellogg/GaussianSplats3D](https://github.com/mkkellogg/GaussianSplats3D) | 功能完整的 Three.js 3DGS 插件，支持 `.ksplat` | 未采用：需要引入其 npm 包与构建链，与「零 npm 依赖 + 离线部署」目标冲突；且其 Three.js 版本耦合较深 |
| [nerfstudio](https://github.com/nerfstudio-project/nerfstudio) | 一站式 NeRF/3DGS 工具链 | 安装体积大、依赖复杂，不适合派出所单机部署 |
| [Polycam](https://polycam.ai/) / [Luma AI](https://lumalabs.ai/) | 手机端一键重建，导出 `.glb` / `.ply` | **推荐作为无显卡时的替代路线**：手机拍一圈 → 导出 `.ply` → 用 `pipeline/to_splat.py` 转 `.splat` 即可在本系统查看（见部署文档 §6） |
| [CloudCompare](https://www.cloudcompare.org/) | 点云配准 | 未集成；系统内部的「多源对齐」走 PnP 路线，更贴合监控摄像头的标定需求 |
| [Make (Integromat)](https://www.make.com/) | 蓝图中提到的流程编排 | **未采用**：属于云端 SaaS，与「开源自部署、数据不出内网」的合规要求冲突。系统内的流程编排由 `app/server/index.js` 的 REST + WebSocket 事件承担 |
| [Cursor](https://cursor.com/) | 蓝图中提到的 AI 编码工具 | 开发工具，不是运行时依赖 |

## 二、许可证合规提示

- **Three.js**：MIT，可商用，已在 `vendor/three/LICENSE` 保留原始许可证
- **imageio-ffmpeg**：它只是**下载并打包** ffmpeg 二进制；ffmpeg 本体的许可取决于编译选项。
  本项目使用的 `ffmpeg-win-x86_64-v7.1.exe` 是 essentials 构建。
  **若要对外发行，请自行确认 ffmpeg 的 LGPL/GPL 合规性**（内部分发通常无碍，商业分发需注意）
- **plyfile**：GPL-3.0 / MIT 双许可，按 MIT 使用
- **PyTorch / NumPy / OpenCV**：均为宽松许可证（BSD / Apache-2.0），可商用
- 本项目自研代码未声明许可证，**请根据单位要求补充**（警务项目通常为内部使用）

## 三、环境实测记录（本机）

| 项 | 值 |
| --- | --- |
| 操作系统 | Windows 11（build 26200，25H2） |
| GPU | NVIDIA GeForce RTX 5060 Laptop GPU，8GB，算力 **sm_120** |
| 驱动 / CUDA | 610.62 / CUDA UMD 13.3；已装 CUDA Toolkit **12.8**（含 nvcc） |
| 编译器 | **无 MSVC**（未安装 Visual Studio / Build Tools）→ 无法编译任何 CUDA 扩展 |
| Python | `pyruntime312`（3.12.10 embeddable，`pydeps312`）+ 系统 Python 3.13.2 |
| PyTorch | **2.7.1+cu128**（`arch list` 含 `sm_120`，GPU 矩阵乘实测通过） |
| 网络 | PyPI 走清华镜像约 2.9MB/s；GitHub 直连仅 40~60KB/s |

因此本项目的技术选型遵循一条硬约束：**在「没有编译器、GitHub 很慢」的机器上也要能跑通**。
所有需要编译的组件（COLMAP、gsplat、原版 3DGS）都被替换为「预编译轮子」或「纯 PyTorch 自研实现」。
