# 21:07–22:00 一小时：COLMAP(global) 路线实测结论（重要，改变交付方案）

## 一、三个训练配置的实测（宿舍，COLMAP global 模型，210 帧）

| 配置 | 高斯数 | 平均 PSNR | 观感 |
| --- | --- | --- | --- |
| `densify 5e-3`（专家建议值） | **3,986** | 11.88 dB | 几乎没东西（分裂被"饿死"） |
| `densify 5e-4` | 17,426 | 11.26 dB | 同上 |
| `densify 1e-4 + max 40 万` | **62,798** | **12.32 dB** | 大量大而淡的白球，房间盒被拉成 21.41 单位 |

对比：**VGGT 路线 16.37 dB（133 万高斯）、增量 COLMAP 14.76 dB**。

**结论：COLMAP(global) 做渲染明显更差。** 内参不是原因（fx 1814 vs 1754，接近）；
更可能是全局法的位姿对"光度一致性"不友好（重投影 1.69 px），而 210 帧 × 20k 步也偏少。

## 二、但 COLMAP(global) 的结构判定明显更好

| 指标 | VGGT | COLMAP(global) |
| --- | --- | --- |
| 场景判定 | ⚠ 不确定（方向包围度 0.13） | ✅ **房间**（0.59） |
| 可信竖墙 | 0~8 面 | **7 面** |
| 房间高度 | — | **2.39 m**（很合理） |
| 房间长边 | 1.12 单位 | 21.41 单位（**被拉长，不可用**） |

## 三、因此调整交付方案（重要）

**不把主路线整体切回 COLMAP，而是"各取所长"**：

| 用途 | 用哪个 | 理由 |
| --- | --- | --- |
| 演示的**渲染模型**（要好看） | **VGGT 路线**（`宿舍现场-彩色.splat`，133 万高斯、16.37 dB） | PSNR 明显更高、彩色、盒子已对齐 |
| 演示的**结构线**（要判对） | **COLMAP(global)** 的 `structure.json`（房间 + 7 墙 + 高度 2.39 m） | 判定正确 |
| 家具盒 | VGGT 路线（坐标已对齐） | 免去 2 小时坐标对齐 |

## 1. 模型抽稀（免重训，解决高斯过多/手机卡）

  排序耗时 30.7 → 13.7 ms 是真实收益。
- 产出：`data/models/宿舍现场-彩色-精简.splat`

## 2. 盒子去重（专家 Q5，解决"重合体积大"）

新工具 `tools/nms_boxes.py`：
1. **类别层次消解**（`--iou-hierarchy 0.2`）：`bunk bed`→抑制`bed`、`bed`→抑制`sofa`
2. **跨类别 3D IoU NMS**（`--iou 0.45`，按专家建议）
3. 置信度降序，相近时保留体积大的

**为什么要两个阈值**（实测数据）：
- `bed` 与 `sofa` 的 3D IoU 只有 **0.25 / 0.35**（同一片区域被识成两类）→ 0.45 的几何阈值去不掉
- `door` 与 `cabinet` 的 IoU 是 **0.28**，但它们是**相邻的两个真实物体** → 不能合并

结果：**7 → 5 个盒子**，去掉的 2 个都是床区域的 sofa 误检，门/柜子/桌/椅都保留 ✓
`data/models/宿舍现场-彩色-精简.furniture.json` 已更新。
