# 交付说明（11-05 版）

> 给评审看的两样东西：**一个能扫码打开的网址**，和**一个能在电脑上跑起来的本地服务**。
> 本文件说明它们分别能做什么、怎么启动、文件在哪。

## 一、两种打开方式（用途不同，别混）

| | ① 手机扫码（静态版） | ② 电脑本地服务（完整版） |
| --- | --- | --- |
| 地址 | `https://<你的项目>.pages.dev` | `http://127.0.0.1:8787` |
| 需要我的电脑开着吗 | **不需要**（文件在 Cloudflare CDN 上） | **需要** |
| 能看模型 / 转视角 / 结构线 / 家具盒 / 测量 | ✅ | ✅ |
| 上传视频 / 开始建模 / 多人协同 / 标注保存 | ❌ **只读** | ✅ |
| 适合 | 评审自己扫码看 | 现场演示建模与协同 |

> 一句话：**扫码看效果，本地演能力。**

## 二、静态版（扫码）怎么部署 —— 按 2026-11 当前界面

### 路线 A：Cloudflare Pages（推荐）

1. 直接打开这个链接（省得找菜单）：
   **https://dash.cloudflare.com/?to=/:account/workers-and-pages**
2. 点右上/页面中央的 **Create application**（创建应用）
3. 在弹层里点 **Get started**（开始），然后选 **Drag and drop your files**（拖拽上传文件）
   > 注意：**不要选** "Connect to Git"（那是接代码仓库的）
4. 填 **Project name**（项目名，随便起英文，如 `case-scene`），会变成 `case-scene.pages.dev`
5. 把 **`dist-static` 这个文件夹**整个拖进上传框（也可以先压成 zip 再拖）
6. 点 **Deploy site**（部署站点）→ 等 10~30 秒 → 得到 `https://case-scene.pages.dev`

**为什么现在能拖上去了**：官方限制「拖拽上传 **最多 1,000 个文件**」，
我们原来整包 **1,148 个**（three.js 的示例文件几乎都用不到）会超限。
现在 `build_static.py` 改成**按代码里的 import 精确拷贝 + 追踪依赖闭包**，
只有 **34 个文件 / 22 MB**，最大单文件 11.3 MB（限制 25 MB）✅

### 路线 B：如果 A 实在找不到入口

用 **Netlify Drop**：打开 https://app.netlify.com/drop → 把 `dist-static` 文件夹拖进去 →
立刻得到 `https://xxx.netlify.app`（可能要求登录）。功能与 Pages 一致。

## 三、本地服务怎么启动

```bat
REM 在项目根目录
set PORT=8787
node app\server\index.js
```
浏览器打开 `http://127.0.0.1:8787`。零 npm 依赖，只需要 Node。

**建模流程**（完整版才有）：选案件 → 上传视频 → 点「开始建模」→ 等 5~30 分钟 → 自动载入结果。

## 六、已知限制（主动说明，别被问住）

1. **静态版是只读的**：上传/建模/协同/标注保存都不可用（会提示"只读演示版"）。
2. **尺度未标定前一律写"单位"**：SfM 的尺度是任意的，填了卷尺实测值才换算成米。
3. **单墙补全的房间盒是虚线 + "推测"**：实测误差 10~19%，系统主动标注，不当测量结果用。
4. **部分视角的家具盒只有可见部分**（如宿舍的床只量到下半层），所以尺寸偏小。
5. **手机端只做查看**，不做重建（端侧实时重建学术上可行，本期是工程取舍）。

# 线上 bug 修复记录：下拉框加载丢 structureUrl（11-04 下午）

## 症状（用户实测）

线上 `https://case-scene.pages.dev/` 选了 `room-real`，**结构线一条都没有**；
但同一份模型在启动时自动加载 / 直接调 `loadModel()` 是有结构线的。

## 根因（两个叠加，都是"假控件"类问题）

1. **下拉框没有 change 监听**：只有"选中 + 点『载入三维现场』按钮"或"双击"才加载。
   用户（和评审）会预期"选了就出现"，于是以为功能坏了。
2. **`onLoadModel(url)` 把清单里的完整对象丢了**：
   它只拼了 `{ name, url }`，**`structureUrl` 没了** → `applyStructure` 第一行就 early-return
   → 结构线永远不画。而 `applyStructure` 只认 `model.structureUrl`，不会自己拼。

## 修复

| 位置 | 改动 |
| --- | --- |
| `app.js` `updateModelList()` | 把清单存进 `state.models`（原来只传给 UI） |
| `app.js` `onLoadModel(url)` | 按 URL 从 `state.models` 找**完整对象**；找不到就**再取一次清单**兜底 |
| `ui.js` | 下拉框加 `change` 监听 → **选完直接载入**（保留双击/按钮） |
| `app.js` 覆盖提示 | 原来是**模态框**，正好盖住模型与结构线（用户以为"线没了"）→ 改 toast，并**合并进"已载入"那条**（否则会被覆盖） |
| `app.js` 推测盒抑制 | **已回退**：它把「单墙补全 → 虚线推测盒」这个卖点功能压掉了（`browser_estimated_room` 8 项失败），而收益只是"厕所那个离谱盒子"，而厕所已从演示包删除 |

## 新增回归测试

`tests/browser_model_dropdown.mjs`（**7 项**）：下拉框选项存在 → dispatch change →
模型真的换（高斯数变化）→ **`structureUrl` 没丢** → 结构线画出（segments>0）→ 场景判定 room。

在**本地服务和静态包上各跑一遍**都 7/7。
