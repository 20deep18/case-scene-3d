## 二、① 的详细设计（下一步就从这里开始）

**当前判据（有逻辑缺陷，必须换掉）**：
```python
# tools/scene_structure.py 里
scene_mode = "room" if (len(real_walls) >= 2 and _cam_ok) else "object"
```
`_cam_ok` 判的是"相机高度是否合理（0.6~2.6 m、地面以下 ≤5%）"。
**问题：这次判成 `object` 的唯一原因是"30 个相机在'地面'以下"，而那个"地面"正是拟合失败的产物。
用下游失败的证据做上游分类判断是危险的 —— 地面一旦碰巧拟合成功，柜子就会被当成房间，然后一路错下去。**

**新判据（不依赖任何拟合，只用相机位姿）—— 用「视线汇聚度」**

先说**为什么"相机在点云凸包内/外"这个方案不行**（我推演过，算出来是错的，别重复走）：
柜子那组实测 **相机跨度 12.5 m，而点云稳健跨度 25 m** —— 点云半径（12.5 m）比相机环绕半径（6 m）**还大**。
因为点云里混进了大量背景点（这正是要靠第④步背景分离解决的问题）。
所以任何"相机 vs 点云半径"的比值判据，在这种点云上都会把**物体误判成房间**。
**结论：判据不能建立在点云尺度上，因为点云质量本身是不可靠的输入。**

**改用只依赖相机位姿的判据：视线汇聚度。**

本质区别：
- **物体拍摄**：相机绕着物体转，**视线大致都指向同一个中心**（物体）。
- **房间走动**：相机在不同位置看向**不同的墙**，视线**不汇聚**。

量化方法（一维优化，很好实现）：
```
对每个相机 i，取其视线方向 f_i（世界系）与位置 c_i
候选汇聚距离 d，令 q_i(d) = c_i + f_i · d
定义 spread(d) = q_i(d) 的离散程度（如到其中位点的平均距离，归一化到场景尺度）
求 d* = argmin spread(d)，取 minSpread = spread(d*)
```
- 物体：存在 d* 使所有 q_i 聚成一小团 → **minSpread 很小**（相对场景尺度，比如 < 0.25）
- 房间：无论 d 取多少，q_i 都散开 → minSpread 大

实现要点：
- `d` 的搜索范围用相机轨迹跨度的 0.3~3 倍即可，粗扫 + 二分足够。
- 视线方向取相机姿态的 **-Z 方向**（见 `camera-overlay.js` 的约定：局部 -Z 是观察方向）。
- **把 `minSpread`、`d*`、以及"相机到点云中心的距离分布"一起写进结构文件**（`sceneModeEvidence`），
  便于事后复盘与调阈值 —— **不要只写一个布尔结论**（这是我在别处踩过的教训）。

**两个判据一起用**：`minSpread` 小 → 物体；再叠加原有的"地面/相机高度是否自洽"作为**佐证**（而不是主判据）。

## 三、③ 的已知线索（`density_peak` 谐波）

实测这份柜子模型，水平层输出 5 个峰，**连续两层间距精确等于 0.583 m**，这不是搁板会有的样子，是**周期性伪影**：

```
#0 -1.2113 m   #1 -0.6285 m（间距 0.583）  #2 -0.0458 m（间距 0.583）  #3 0.8282 m  #4 2.5764 m
```

怀疑 `density_peak()`（我自己写的，在 `tools/scene_structure.py`）返回**谐波峰**：
它按固定 bin 宽找最大 bin，调用方挖掉 ±3 bin 再找下一个，残留可能在相邻位置再生峰。

**建议改法**：改成"先找所有**局部极大** bin，再按 **prominence**（与相邻谷底的高差）筛选"，
而不是"找最大 bin → 挖掉 → 再找"。改完立刻能用同一份数据验证层数是否从 5 收到合理的 2~3。

## 四、④ 背景分离的可靠方案（用户点名要可靠做法）

**技术路径**：
1. **交互**：在某个关键帧上画框（或点选前景/背景）。
2. **分割**：项目里 **cv2 可用**（`config.has_cv2()` 为真），用 `cv2.grabCut()` 做框选分割 → 二值 mask。
3. **传播**：相邻帧用上一帧结果作为 GrabCut 的初始化，逐帧推进（视频帧率低、相邻帧相似度高，传播很稳）。
4. **接入 COLMAP**：`feature_extractor` 支持 `--ImageReader.mask_path`，
   mask 文件名须与图片同名，PNG，**黑=忽略该区域**。
5. **接入训练**：`train_gsplat.py` 计算损失时按 mask 加权/忽略（mask 外不计入 L1/SSIM）。
6. **效果预期**：直接消除用户抱怨的两件事 ——「柜子之外还有很多高斯」「拍摄点附近凑成一团」。

**注意**：mask 是**物体算法专有**步骤，场景算法不该有。这正印证"两套算法"的必要性。

### 关键判据阈值（实测得来，**不要凭感觉改**）

- **针状度 `s1/s2`**：健康 0.472；病态 0.089~0.320。**>0.4 算健康**。
  - 判据来源：`np.sort(scale,axis=1)` → `(s0,s1,s2)`，取 `median(s1/s2)`。
  - **注意区分"针"与"薄片"**：两者 `s0/s2` 都接近 0，区别在**中间轴**。薄片 `s1/s2` 接近 1。
- **`>0.5 m` 高斯占比**：健康 0%；发雾模型 27%~57%。**目标 0%**。
- **雾占比**（大+白+淡 = `s2>0.5 & min(RGB)>200 & alpha<0.6`）：健康 0%。**目标 0%**。
- **alpha 中位**：所有真实模型都在 0.02~0.08，**这是本流水线的常态，不是病**。
  ⚠️ **不要用"提高 `--min-opacity`"去治雾** —— 实测 `room-real` 的 alpha 中位（0.020）
  比病态模型（0.031）**还低**，一刀切会误伤健康模型 68%。**真正的判别指标是针状度。**
