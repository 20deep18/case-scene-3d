# 部署与使用说明

> 面向使用者与运维人员。按本文从零到可用大约需要 **10 分钟**（本机已就绪，只需第 2 步）。
> 完整排错请看文末「常见问题」。

---

## 一、系统要求

| 项 | 最低 | 推荐 |
| --- | --- | --- |
| 操作系统 | Windows 10/11、Ubuntu 20.04+ | Windows 11 + WSL2 或原生 |
| Node.js | 18 | 20 / 22 / 24 |
| 浏览器 | Chrome / Edge 113（需 WebGL2） | 最新版 Chrome/Edge，开启硬件加速 |
| 内存 | 8GB | 16GB 以上（训练时吃内存） |
| 显卡 | 无（仅浏览与协同） | NVIDIA RTX 30/40/50 系，显存 ≥ 8GB（训练） |
| 磁盘 | 5GB（浏览） | 30GB 以上（存放抽帧图与训练中间产物） |

**只需要浏览与协同**：装 Node.js 即可，不需要显卡、不需要 Python。
**需要自己重建现场**：还需要 Python + PyTorch(CUDA) + COLMAP + ffmpeg。

## 二、启动系统（3 步）

```powershell
cd <项目目录>

# 第 1 步：环境自检（可选，但建议先跑一次）
.\start.ps1 -Check

# 第 2 步：启动服务并自动打开浏览器
.\start.ps1 -OpenBrowser

# 第 3 步：浏览器里操作
#   ①「新建案件」填入案件名
#   ② 在「模型文件」里选一个三维现场（如 sample-room.splat）
#   ③ 点「载入三维现场」
```

也可以直接双击 **`启动系统.bat`**。

### 验证多人协同

1. 打开第二个浏览器窗口（或另一台电脑访问 `http://<本机IP>:8787/`）
2. 用同一个案件进入（URL 里带上 `?case=<案件ID>` 更直接）
3. 两边都会看到对方：
   - 顶部头像列表出现对方
   - 对方的视角用彩色视锥体表示（会跟随移动）
   - 一端打点标注，另一端**立刻**出现
4. 底部聊天框可以文字交流

> 首次进入时请在左侧栏修改昵称，否则会随机分配「民警XXX」。

| 左侧 | 案件选择、模型选择、图层开关、在线名单、渲染参数（高斯尺寸/不透明度/曝光/排序开关） |

### 研判工具用法

| 工具 | 操作 | 结果 |
| --- | --- | --- |
| 打点 | 左键点击现场任意表面 | 生成一个物证点，带引线与名称标签 |
| 轨迹 | 沿路线依次点击，双击/回车结束 | 生成轨迹曲线，标签实时显示**总长度（米）** |
| 测距 | 点击两个点 | 生成测距线，标签显示**精确距离（米）** |
| 区域 | 依次点击顶点，双击/回车闭合 | 生成半透明区域面 |
| 相机 | 先点机位，再点画面中心目标 | 生成监控相机视锥；再导入视频即可贴回现场，之后可用「PnP 标定」精确定位 |

**拖动**：选中标注后，拖动其顶点即可微调位置（打点/轨迹/区域/测距都支持；相机是拖机位）。

### 图层与标注列表

**图层面板**（左侧「图层」区）按类型分组，每行包含：

- **▸/▾**：展开该类型，看到**具体是哪几个对象**（例如「物证·玻璃杯」「物证·鞋印」）；点条目即选中并定位到它
- **👁**：一键隐藏/显示该整类标注（三维里立即生效）
- **数字**：该类对象数量

**标注与物证列表**（右侧）交互：

| 操作 | 效果 |
| --- | --- |
| 单击列表项 | 选中该对象并**自动定位** |
| 双击列表项 | 同样只是定位（**不是**删除） |
| 点行尾的 ✕ | 删除该对象，会弹出二次确认 |

> 早期版本「双击 = 删除」，想双击定位时极易误删对象，已改为需要显式点删除按钮并确认。

### 关于帧率

顶部显示的 FPS 采用 500ms 固定时间窗统计。渲染循环设有 **60FPS 上限**：
距上一帧不足 16.67ms 时会先等待再申请下一帧，不会空转把 GPU 和电量吃满。
页面切到后台会自动暂停渲染，回到前台再恢复。

## 四、导入监控 / 勘查视频并贴回现场

1. 底部「多源画面」右侧点「**+ 导入监控/勘查视频**」
2. 选择本地视频文件（支持 mp4 / webm / mkv / mov），填写名称
3. 上传后底部出现画面卡片，三维场景里出现对应的相机视锥。
   新相机会**自动放在场景外侧、朝向场景中心**，这样它一定在可见范围内
   （早期版本固定建在原点，常常落在墙体内部，看起来像「没反应」）
4. 点卡片上的「**贴回现场**」，视角会跳到该相机的拍摄位置 —— 此时视频画面应与现场重合
5. 若没重合，用「相机」工具重新标定：先点机位，再点画面里应该出现的目标点

> 真正的精确定标需要 PnP 解算（见下一节）。手点两个点只适合快速摆放。

**看不到画面？** 依次检查：

- 浏览器控制台是否有 `[camera-overlay] 视频加载失败` —— 说明媒体文件没取到
- 直接访问该视频 URL（形如 `/media/<案件ID>/media/<文件名>`）能否播放 —— 不能则是后端问题
- 视频编码是否为浏览器支持的 H.264/H.265；`mkv` 等容器可能需要先转码成 mp4

> 早期版本上传接口返回的 URL 少了一段 `media`，导致所有视频与图片都 404（表现为黑屏），
> 已修复。`tests/repro_video_upload.mjs` 会做字节级校验防止回归。

## 五、多源对齐：PnP 相机标定

系统内置了纯 JavaScript 的 PnP 解算器（`app/web/js/pnp.js`），无需 OpenCV。

### 原理

给 n ≥ 4 组「**三维点 ↔ 画面像素点**」对应关系，解出监控相机的位姿：

1. 畸变矫正到归一化像平面
2. **DLT**（直接线性法）：对 AᵀA 做 Jacobi 特征分解取零空间，并做 **Hartley 归一化**保证数值稳定
3. 由 P 恢复位姿：相机中心 `C = -M⁻¹p₄`（尺度无关），旋转由 `K⁻¹M` 正交化得到，尺度用奇异值确定
4. **Levenberg–Marquardt** 最小化稳健重投影误差（Cauchy 损失）

实测精度（`tests/test_pnp.mjs` 与 `tests/test_pnp_panel.mjs`）：
- 无噪声：相机中心误差 **1.3e-15 m**，重投影误差 **1.7e-13 px**
- 面板链路（`solveFromPairs`）：相机中心误差 **2.0e-15 m**，重投影误差 **5.7e-13 px**
- 含畸变 + 1.5px 噪声：重投影误差 **0.56 px**（提供畸变系数）、**9.4 px**（不给畸变系数）

### 使用方式（命令行验证）

```powershell
# PnP 解算器本身
node tests\test_pnp.mjs

# 标定面板的完整逻辑（对应点评估、解算、残差、投影一致性、坐标换算）
node tests\test_pnp_panel.mjs

# 浏览器里的面板（需要先启动服务）
node tests\browser_pnp_panel.mjs
```

### 在浏览器里交互式标定（推荐）

系统内置了可视化标定面板，**全程在浏览器里完成，不需要后端参与**。

**打开方式**（任选其一）：

- 底部「多源画面」里，画面卡片上的 **「PnP 标定」** 按钮
- 选中相机对象后，右侧属性面板里的 **「PnP 标定…」** 按钮

**操作步骤**（面板顶部有两个子选项，在同一个小窗口里切换）：

| 子选项 | 操作 |
| --- | --- |
| **① 点画面特征点** | 用播放条或 ◀ ▶ 找到一帧清晰的画面，在画面上点一个**容易辨认**的特征点（墙角、门框角、物证边角）。面板会自动切到子选项 ② |
| **② 点三维对应点** | 到右侧三维视口里点**同一个物理位置**（视口会有黄色虚线描边提示） |
| 重复 | 切回子选项 ① 点下一个像素，再切到 ② 点对应位置 |
| 数量 | **至少 4 组，建议 6~8 组**，且尽量**分散到画面各处** |
| 内参 | 确认「相机内参」（不知道就按视场角估算，监控头常见 60°~90°）；两步都可见 |
| 解算 | 点 **「解算并贴回现场」** |

解算完成后：

- 面板会显示**平均/最大重投影误差**，并在画面上用**红色虚线圆圈**标出每个点的重投影位置
  —— 与你的黄色编号点偏得越远，说明那一组对应点选得越不准
- 相机位姿会写回该标注（`pose.source = "pnp"`），卡片状态从「未标定」变为 `PnP x.xx px`
- 相机视锥与视频画面会立刻按新位姿贴回现场

**提高精度的要点**：

- 对应点要**分散**：全挤在一个角上精度会明显变差（面板会给出「过于集中」的警告）
- 三维侧要**点在高斯表面**（墙面、地面、桌面），不要点在空气里
- 优先选**几何上明确**的角点，避免选模糊边缘
- 重投影误差 **< 2px** 算好；**> 5px** 建议检查是否有误点（列表里残差最大的那几行）
- 若误差偏大，用「撤销上一个点」删掉可疑点重选，或在右侧手动填写真实内参

**关于内参**：监控摄像头的真实内参一般拿不到。面板默认按「水平视场角」估算
（<code>fx = fy = 0.5·H / tan(fov/2)</code>）。若你知道摄像头的焦距与传感器尺寸，
可以在面板右侧直接填写 fx/fy/cx/cy，精度会明显提升。

> 若对画面点击后三维侧提示「这里没有可拾取的高斯点」，说明该处点云太稀疏，
> 换一处（如墙面、地面）再点即可。

## 六、自己重建一个真实现场

### 6.1 采集要点（决定成模型质量，占 80%）

- 手机**慢走环绕**目标 2~3 圈，每圈换一个高度
- 相邻画面重叠 **≥ 70%**
- 光线均匀，避开玻璃、镜面、纯白墙、强反光
- **先用桌面小物体练手**，不要一上来拍整个房间
- 视频编码用 H.264 即可；4K 没必要，1080p 足够

### 6.2 一键流水线（推荐）

```powershell
# 把视频放到 data\scene\input.mp4，然后：
.\重建流水线.bat
# 或指定视频：
.\重建流水线.bat "D:\我的视频\现场.mp4"
```

它会依次执行：抽帧 → COLMAP 位姿 → GPU 训练 → 导出 `.splat`。

### 6.3 分步执行（排错时用）

```powershell
$PY = "pyruntime312\python.exe"

# ① 抽帧（含模糊帧自动剔除）
& $PY pipeline\extract_frames.py --video data\scene\input.mp4 --out data\scene\images --fps 2 --long-side 1600

# ② COLMAP 相机位姿（需要已安装 COLMAP；详见 §7）
& $PY pipeline\colmap_recon.py --images data\scene\images --workspace data\scene\colmap

# ③ 整理成训练目录（images/ + sparse/0/）
mkdir data\scene\gs\sparse -Force
copy data\scene\images data\scene\gs\images -Recurse
copy data\scene\colmap\sparse\0 data\scene\gs\sparse\0 -Recurse

# ④ GPU 训练（纯 PyTorch，无需编译器）
& $PY pipeline\train_gpu.py --data data\scene\gs --out data\scene\output --iterations 15000 --downscale 2 --max-gaussians 300000

# ⑤ 导出浏览器格式
& $PY pipeline\to_splat.py --ply data\scene\output\point_cloud\iteration_15000\point_cloud.ply --out data\models\my-scene.splat --json data\models\my-scene.json
```

然后在浏览器左侧「模型文件」里选择 `my-scene.splat` 即可。

### 6.4 训练参数速查

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--iterations` | 15000 | 迭代次数。桌面小场景 7000 就够；房间建议 15000~30000 |
| `--downscale` | 2 | 图像降采样。**显存不足就调大**（4 或 6） |
| `--max-gaussians` | 400000 | 高斯数量上限。显存 8GB 建议不超过 30 万 |
| `--sh-degree` | 0 | 球谐阶数。0 最快；要表现高光反射可用 1~3（体积变大） |
| `--densify-until` | 0.6×iters | 致密化停止的迭代数 |
| `--debug-numeric` | 关 | 每步打印数值诊断，排查发散用 |

**显存速查（8GB 卡）**：`--downscale 2 --max-gaussians 200000` 大约占 3~4GB；
`--downscale 1` 且点数多时会接近上限，建议先用默认值跑通再加码。

### 6.5 用手机 App 代替 COLMAP（无显卡/无 COLMAP 时的替代路线）

1. 手机装 **Polycam** 或 **Luma AI**
2. 环绕现场拍一圈，App 自动重建
3. 导出 **`.ply`**（Luma 支持导出 ply；Polycam 可导出 ply/obj）
4. 转换成本系统格式：

```powershell
pyruntime312\python.exe pipeline\to_splat.py --ply "手机导出的.ply" --out data\models\phone-scene.splat --json data\models\phone-scene.json
```

5. 浏览器里加载 `phone-scene.splat`

> 注意：手机 App 导出的是**带真实颜色**的 `.ply`（不是 3DGS 的高斯 PLY），
> `to_splat.py` 会按点云的 x/y/z + red/green/blue 解析，把它变成"小球拼成的场景"，
> 视觉上不如 3DGS 细腻，但空间关系是准的，完全可以用来做研判与标注。

## 七、安装 COLMAP（真实拍摄必需）

本机**没有安装 COLMAP**，因为它是 C++ 项目，官方只提供 Windows 预编译包（约 415MB），
而本机下载该包的速度约 40KB/s（需 ~3 小时）。安装方式：

### 方式 A：下载官方预编译包（推荐）

1. 访问 <https://github.com/colmap/colmap/releases>
2. 下载 `colmap-x64-windows-cuda.zip`（约 415MB，**CUDA 版**训练更快）
3. 解压到任意目录，例如 `C:\tools\colmap`
4. 把 `C:\tools\colmap\bin` 加入系统 PATH
5. 验证：`colmap -h`

> 也可以设置环境变量 `DSH_COLMAP` 指向 `colmap.exe` 的绝对路径，无需改 PATH。

### 方式 B：conda（跨平台最省事）

```bash
conda create -n colmap -c conda-forge colmap -y
conda activate colmap
colmap -h
```

### 方式 C：WSL2 / Ubuntu

```bash
sudo apt install colmap
```

> 用 WSL 时注意路径映射：Windows 的 `D:\data` 在 WSL 里是 `/mnt/d/data`。

### 方式 D：pycolmap（需要 Python 3.10）

```powershell
# 注意：官方 PyPI 只有 cp310 轮子，且不是 abi3，Python 3.11+ 装了会 import 失败
pyruntime310\python.exe -m pip install pycolmap
```

## 九、常见问题

### 启动相关

**Q：双击 `启动系统.bat` 一闪而过**
A：用 PowerShell 运行 `.\start.ps1`，能看到完整错误。通常是没装 Node.js。

**Q：浏览器打开是白屏**
A：按 F12 看 Console。
- 提示 `WebGL2 not supported` → 升级 Chrome/Edge 到 113+，或在设置里开启「使用硬件加速」
- 提示 404 → 确认服务已启动，且端口没被占用

**Q：端口 8787 被占用**
A：`.\start.ps1 -Port 9000`，或用 `netstat -ano | findstr 8787` 找到占用进程。

### COLMAP 相关

**Q：COLMAP 在哪、怎么确认能用**
A：官方 CUDA 版已解压在 `tools\colmap\`，`config.find_colmap()` 会自动找到它，**无需配置**。

```powershell
# 确认能找到
pyruntime312\python.exe -c "import sys; sys.path.insert(0,'pipeline'); import config; print(config.find_colmap())"
# C:\...\tools\colmap\bin\colmap.exe

# 端到端验证（自动跑 feature_extractor → matcher → mapper，并给出权威统计）
pyruntime312\python.exe tools\verify_colmap.py --images <图片目录> --workspace output\colmap-verify
```

详细说明见 **[COLMAP安装与验证.md](COLMAP安装与验证.md)**。

**Q：COLMAP 报 `unrecognised option '--SiftExtraction.use_gpu'`**
A：COLMAP 4.x 把选项改名了（`SiftExtraction.*` → `FeatureExtraction.*`，`SiftMatching.*` → `FeatureMatching.*`）。
本项目的 `pipeline/colmap_recon.py` 会**先探测 `--help` 里真实支持的选项名再选用**，3.x / 4.x 都能跑。
若你在别的脚本里写死了旧名，改成新名即可。

**Q：COLMAP 报 `output_path is not a directory`**
A：`mapper` 要求 `--output_path` 指向**已存在**的目录。本项目的流水线会自动创建。

**Q：`colmap model_converter` 崩溃（退出码 0xC0000409）**
A：COLMAP 4.2.1 在 Windows 上的已知问题。改用
`tools/colmap_model_io.py` 读二进制模型，或用 `colmap model_analyzer --path <模型目录>` 看统计。

**Q：COLMAP 找到了特征但匹配数为 0（`Failed to create any sparse model`）**
A：**图片缺少纹理**。纯色墙面、白墙、玻璃幕墙都会让 SIFT 找不到点
（实测纯色合成房间每张只有 28~50 个特征点，匹配数为 0）。
用 `tools/make_textured_dataset.py` 生成的纹理场景可以看到正常效果；
真实拍摄时画面里必须有纹理细节。

**Q：改了代码刷新页面却没生效**
A：服务端已对 HTML/JS/CSS 设置 `Cache-Control: no-store`，正常不会命中缓存。
若仍异常用 **Ctrl+F5** 硬刷新。早期版本用的是 `no-cache`，浏览器可能继续使用内存里的旧副本，
会出现「新面板/新行为没出现」的假象——排查这类问题非常费时，所以现在直接禁用缓存。

### 渲染相关

**Q：场景一片黑 / 什么都看不到**
A：按下面顺序排查：

1. 看右下角加载进度条是否走完；走完时中间会弹「已载入 N 个高斯球」
2. 点左侧「渲染参数」把「**高斯尺寸**」滑块往右拉 —— 低分辨率训练的模型高斯很小，
   调大后立刻能看到结构
3. 按 F12 看 Console：
   - `顶点着色器编译失败：...` → 已在 v1.0.1 修复（GLSL ES 3.00 没有 `transpose()`）；
     若仍出现，把报错里的**带行号源码**整段发出来
   - `[splat-renderer] 顶点属性装配异常` → 渲染器自检发现属性没启用，属于渲染器 bug
4. 在 Console 里执行 `__caseSystem.state.renderer.stats` 看 `drawn` 是否等于高斯总数、
   `lastDrawError` 是否为 0

> v1.0.0 曾有一个非常隐蔽的缺陷：顶点属性 `location=0` 被 `!attrName` 误判为无效，
> 导致 `position` 永不启用 → 所有高斯都被视作在相机背后 → 画面全黑。
> 现在 `setData()` 会自检并在 Console 明确报错。详见[验证报告 §6.2](验证与测试报告.md)。

**Q：导入视频后卡片是黑的 / 贴回现场看不到画面**
A：① 看 Console 有没有 `[camera-overlay] 视频加载失败`；
② 用浏览器直接打开视频 URL（`/media/<案件ID>/media/<文件名>`）确认后端能取到文件；
③ 视频编码需是浏览器支持的 H.264/H.265，`mkv`/`ts` 等建议先转成 mp4；
④ 点卡片上的「贴回现场」把视角移到机位附近，画面在相机前方 60m 处。
（v1.0.0 的上传 URL 少了一段 `media`，导致全部 404 黑屏，已修复。）

**Q：只导入了一个视频，却出现两个相机对象**
A：v1.0.0 的「带 id 再次提交」会新增而不是更新。现已改为幂等 upsert，
`tests/test_annotation_idempotent.mjs` 会守住这一点。若你之前已经产生了重复对象，
直接在标注列表里删掉多余的那个即可。

**Q：FPS 显示 60000 之类的离谱数字**
A：v1.0.0 用逐帧 `1/dt` 累加，极小的时间间隔会算出上千的瞬时值。现已改为
500ms 固定时间窗计数，并加了 60FPS 上限。若仍异常，按 F12 看是否有报错。

**Q：很卡**
A：① 关掉「实时视深度排序」；② 用 `pipeline/to_splat.py --decimate 0.5` 抽稀模型；
③ 关掉浏览器其他标签页；④ 确认走的是独立显卡（笔记本插电 + 电源模式「高性能」）。
渲染循环本身已有 60FPS 上限，所以「卡」一般来自模型过大或显卡较弱。

**Q：画面有漂浮物/噪点**
A：训练数据问题，不是渲染问题。回采集阶段：抽帧后手动删掉糊帧、重叠不足的帧；
或训练时提高 `--iterations`、降低 `--densify-grad-threshold`。

### 训练相关

**Q：`CUDA error: no kernel image is available for execution on the device`**
A：PyTorch 版本与显卡算力不匹配。RTX 50 系（sm_120）**必须用 cu128 及以上**：

```powershell
& $PY -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.get_arch_list())"
# 期望看到 sm_120 在 arch list 里
```

**Q：`CUDA out of memory`**
A：按顺序尝试：① `--downscale 4`（或 6）；② `--max-gaussians 100000`；
③ 关掉浏览器占用显存的页面；④ `--sh-degree 0`。

**Q：训练损失不下降 / 一直是同一个数**
A：多半是「图像与 sparse/0 不匹配」（图像名对不上，或用了 undistorted 之后的位姿配原始图）。
检查 `images/` 里的文件名与 `images.bin` 里记录的名字是否一致（大小写敏感）。

**Q：`sparse/0 不存在`**
A：COLMAP 步骤没跑成功。先单独跑 `pipeline/colmap_recon.py` 看报错。

**Q：`稀疏点太少` / 高斯数量上不去**
A：COLMAP 注册的图像太少。增加环绕覆盖、提高帧重叠率、改用 `OPENCV` 相机模型，
或降低 `colmap feature_extractor` 的特征阈值。

### 流水线相关

**Q：`未找到 ffmpeg`**
A：本项目已内置（`imageio-ffmpeg`），确认用的是 `pyruntime312\python.exe`。
要外部安装：`winget install Gyan.FFmpeg`，或设环境变量 `DSH_FFMPEG` 指向 `ffmpeg.exe`。

**Q：抽帧后图片全被判为模糊**（`_rejected/` 里一堆）
A：阈值太严。`--blur-threshold` 调小，例如 `--blur-threshold 30`。

**Q：`to_splat.py` 报「PLY 里只有 0 个 f_rest_* 属性」**
A：正常警告。说明模型是 SH0（不含高阶球谐），会自动降为 0 阶，不影响使用。

### 协同相关

**Q：两人看不到对方**
A：确认两边的「案件」是同一个（URL 里的案件 ID 一致）。顶部连接状态应显示「协同在线」。
若跨网段，注意防火墙需放行 8787 端口。

**Q：改动没有同步到对方**
A：协同时以**服务端为准**。若对方在网络中断期间改了东西，重连后请刷新页面。
