# 给专家的问题清单（2026-11-03 第二轮）

> 背景一句话：管线已能跑通（COLMAP/GLOMAP + VGGT + 3DGS + 检测），
> 现在卡在**末端表达**：家具只有 AABB、盒子互相重叠、3DGS 边缘发白。
> 下面每条都附我们已试过的东西，方便专家直接给判断。

## A. 模型观感

1. **3DGS 边缘发白/发糊**：初始化点已带真实颜色（从图像取色，均值 RGB≈130/125/119），
   但训练 12k 步后，模型外圈仍有大量**大而低不透明度**的高斯，视觉上一片白。
   - 我们的配置：`--iterations 12000 --downscale 1 --sh-degree 0 --densify-grad-threshold 1e-4`
   - 问：这是 densidad 过密（阈值太低）还是迭代不足？推荐的阈值/迭代/`--sh-degree` 组合？
   - 补充：模型 PSNR 16.4 dB（24 帧，手持，室内），是否本身就说明训练不足？

2. **颜色是否应该用 SH**：我们现在 `--sh-degree 0`（只有 DC）。室内有反光/白墙时，
   SH 阶数提高对"看起来不白"有帮助吗？显存/时间代价如何？

## B. 家具盒表达（重点）

3. **多盒分解**：一张上下铺用**一个 AABB** 完全表达不了（床板+床架+护栏+立柱）。
   我们打算在"已检测到的物体点集"内部做**几何分解**（递归二分：按主轴中位数切，
   子集只保留"能被一个盒子拟合得较好"的），产出 2~6 个子盒。
   - 问：这是否是合理路线？有没有更稳的做法（例如先做体素化再连通分量、或做平面/圆柱基元拟合）？
   - 问：**部分视角**下（只看到下半层），子盒会不会越分越碎？有没有"停止分裂"的判据推荐？

4. **部分视角的评测口径**：真值只有整体尺寸（床 2.0×0.8×1.8），可见部分只有下半层。
   - 问：这种"真值全、观测部分"的情况，误差应该怎么报才站得住？
     （我们目前报"测得/真值"的逐项相对误差 + IoU，明显吃亏。）

5. **盒子重叠**：同一区域被检出 `bed` / `bunk bed` / `sofa` 三个类别，三个盒子重叠。
   - 问：跨类别的 3D NMS 是否标准做法？IoU 阈值经验值？
   - 问：视觉上是否应该**只画边线 + 半透明**（不填充）来避免糊成一团？

## C. 检测与深度

6. **上下铺上下两层**：2D 检测 + 深度反投影能否区分上下两层？
   还是需要实例分割（如 SAM）先分离，再各自反投影？

7. **跨帧合并**：我们现在用"场景对角线 × 5%"作合并半径（很土）。
   - 问：业界通常怎么合并跨帧的 3D 检测（3D IoU + 贪心？匈牙利匹配？按轨迹？）

8. **深度边缘飞点**：Realsense 类资料常说边缘会外扩；我们反投影时用 P5~P95 分位截断。
   - 问：是否有更好的做法（双边滤波、法向一致性剔除、或多帧一致性投票）？

## D. 工程取舍（想听专家一句判断）

9. 我们已把建图换成 **COLMAP 的 global_mapper（原 GLOMAP）**：宿舍 211 帧 65 秒 / 210 张注册，
   增量法 8.9 分钟 / 198 张且尺度爆炸。**但重投影误差 1.69 px（增量 1.15 px）**——
   这种"注册更多、残差略高"的权衡，对下游 3DGS 训练是否可接受？

10. 若只做一件事提升"评审可见的质量"，专家会选：
    (a) 多盒分解；(b) 提升 3DGS 训练质量；(c) 用更大帧数/多窗口 VGGT 解决覆盖不全？
