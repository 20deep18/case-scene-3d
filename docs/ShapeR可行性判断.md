# ShapeR 能否接入？—— 基于开源事实的判断（11-04）

> 事实来源：项目页 `facebookresearch.github.io/ShapeR`、GitHub `facebookresearch/ShapeR`
> 的 README / INSTALL.md（2026-11-04 抓取）。

## 一、结论（先给答案）

| 问题 | 答案 |
| --- | --- |
| 能进 **11-05 的交付**吗？ | **不能**。安装本身就要数小时（见下），我们只剩 1.5 小时 |
| 值得**答辩之后**做吗？ | **值得**，约 **2~3 天**（WSL2 环境 + 适配我们的数据） |
| 它是"替换"我们管线吗？ | **不是**。它是**检测/分割之后的一层**：把"AABB 盒子"升级成"带遮挡补全的完整物体网格" |
| 最硬的三个门槛 | ① **只有 Linux 安装说明**（torchsparse 自编译 + flash-attn）② **8 GB 显存**偏紧 ③ **CC-BY-NC 非商用许可** |

## 二、开源事实（决定可行性的部分）

### 安装（INSTALL.md）
- Python 3.10、**CUDA 12.8**、**conda**、`gcc_linux-64=11 / gxx_linux-64=11`
- `flash-attn`（要编译，Ampere 以上）
- **`torchsparse@legacy`**（作者的注释原文：*"This step takes a while, be patient"*）
- `torch-cluster`（pyg 的 wheel）、`pymeshlab`、`sophuspy`、`torchdiffeq` …
- **→ 全文没有 Windows 步骤**。我们机器是 Windows + RTX 5060 8 GB；
  可行路径是 **WSL2**（我们之前已启用 WSL2），但 conda + CUDA + torchsparse 编译
  按经验 **3~6 小时起步，且首次成功率不高**。

### 输入（README「Data Format」）
它**不吃视频**，吃的是**预处理好的 pickle**，每个物体一份，包含：
- 稀疏/稠密 **SLAM 点云**
- **多视角图像 + 相机参数**
- **3D 物体实例**（instance）与 2D 掩码
- **文本描述**（VLM 生成的 caption）
- 2D 点投影

官方流程是 *Aria MPS 管线 + 3D 物体实例检测器*。

### 推理与输出
```bash
python infer_shape.py --input_pkl ADT1292__stool.pkl --config balance
```
- 预设：`quality`（16 视角/50 步）/ **`balance`（16/25，推荐）** / `speed`（4/10，最快）
- 输出：**`<name>.glb` 网格**（+ 可选可视化对比图）
- 权重从 HF 自动下载（`facebook/ShapeR`）

### 许可证
**CC-BY-NC（非商用）**。研究演示可以，**做成对外售卖的产品不行**。

## 三、我们的缺口清单（接入到底还差什么）

| 它需要 | 我们已有 | 缺口 |
| --- | --- | --- |
| 相机位姿 + 点云 | ✅ COLMAP/VGGT | — |
| 多视角图像 | ✅ 抽帧 | — |
| **2D 物体框** | ✅ Grounding DINO | — |
| **实例掩码（mask）** | ❌ 我们只有框 | 需补 SAM2 / Mask2Former（每帧分割），约 0.5~1 天 |
| **3D 实例** | ❌ | 掩码 + 位姿 → 多视角投票融合成 3D 实例，约 0.5 天 |
| **VLM 文本描述** | ❌ | 接一个本地 VLM 或直接写模板 caption（"a bed"），约 2 小时 |
| **pickle 打包** | ❌ | 按 `explore_data.ipynb` 的键名打包，约 0.5 天 |
| **Linux + 编译环境** | ⚠️ WSL2 已启用 | torchsparse/flash-attn 编译，**3~6 小时** |

**合计**：环境 3~6 h + 补齐 1.5~2 天 ≈ **2~3 天**（不含翻车重试）。

## 四、它能解决我们的什么（这才是关键）

我们现在的痛点（用户原话）：**"家具盒重合体积大、不像家具，希望由多个盒子组成、线条更丰富"**。

ShapeR 正好打在这里：
- 输出是**每个物体的完整网格**（含遮挡补全，论文说完整度 62%→89%）
- 物体之间**互不融合**（object-centric），所以"重重叠叠的大盒子"问题自然消失
- 论文明确说：**能从手机随手拍 + MapAnything 的米制点云里重建**（不限于 Aria 眼镜）

换句话说：**它不是替代我们的管线，是把我们的"AABB 盒子"这一层升级成"物体网格"**。
我们已有的位姿/点云/检测正好是它的输入前半段 —— 这个衔接是顺的。

## 五、风险与不建议做的事

| 风险 | 说明 |
| --- | --- |
| 显存 | 16 视角 + 流匹配 Transformer + 3D VAE + DINOv2，8 GB 很可能只能跑 `speed`（4 视角） |
| 编译 | torchsparse legacy 在 WSL2 + CUDA 12.8 上能过，但要预留半天 |
| 许可 | **CC-BY-NC**：答辩/研究演示没问题；若要产品化必须另行授权 |
| 数据 | 它训练于合成数据（Aria SE），我们的宿舍是手机手持 + 弱纹理，效果需实测，**不能预设成功** |

## 六、我的建议（按时间分三层）

### ① 11-05 交付前（1.5 小时）：**不碰 ShapeR**
只做三件事：全量回归、重建静态包、二维码 + 最终截图。
**在 PPT 里留一页"技术前沿对照"**：写明"我们已定位该问题，Meta 2026 的 ShapeR 正是解法
（object-centric 生成式补全，完整度 62%→89%），计划在其上做物体级网格替换"。
—— 这一页的分数比硬塞一个跑不起来的 demo 高得多。

### ② 答辩后 2~3 天：做一次**时间盒 spike**
1. WSL2 + conda 装环境（3~6 h，**先跑通官方示例 `ADT1292__stool.pkl`**）
2. 用 `speed` 预设测**显存与耗时**（能不能塞进 8 GB 是生死线）
3. 若示例跑通：用我们的宿舍素材打包 1 个物体（床）的 pickle，看补全效果
4. **验收**：能输出一个 `.glb` 且肉眼是"床"而不是一团 → 才算成功

### ③ 如果 spike 失败：**退回到 4 小时能做的那招**
我们自己的"多盒分解"（体素连通 + 递归二分）能拿到 60% 的观感收益，且**零新依赖**：
把一个大盒子拆成"床板 + 床架 + 立柱"两三个盒子，线稿立刻有结构感。

## 七、一句话

**ShapeR 是"对的方向、错的时间"**：它精确命中了我们"盒子不像家具"的痛点，
但 Linux 编译 + 8 GB 显存 + CC-BY-NC 三道门槛，决定了它属于**答辩后的路线图**，
而不是明天交付的功能。**PPT 上把它写成"已识别的解法"，比硬塞一个半成品更加分。**
